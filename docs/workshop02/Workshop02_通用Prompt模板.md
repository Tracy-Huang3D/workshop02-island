# Workshop 02｜换成你的主题：通用 Prompt 模板

这份模板配合《Workshop 02：从一个模型出发，搭建自己的 3D 小岛》使用。芽芽的林间花园是示范，你可以做机器人的维修角、企鹅的冰雪营地，或属于自己原创模型的小空间。无需沿用示范中的树、窝、花草、配色或物件数量。

## 复制之前

每个代码框是一条可以单独发送的指令。先把 `【……】` 换成自己的内容，再把整段复制到指定工具。可选字段没有内容时填“无”，不要把括号原样发送。图片要在发送指令时实际上传；写出图片名称不等于工具已经收到图片。

给 Codex 的指令在你打开的练习项目对话中发送。路径使用相对于项目文件夹的路径，不填写电脑用户名。不要在讲师已完成的案例里执行“从头搭建”；为自己的练习准备单独项目文件夹。每一步检查通过后，再发送下一步。

## Step 01｜为主角填写创作卡

**使用工具：** Codex，或你正在使用的文字 AI。**输入：** Workshop 01 的主模型截图和已有设定；没有截图时先提供文字。**替换：** 主角、特征、习惯、环境和情绪。

```text
我正在参加 Workshop 02，要以已有的主模型为中心，设计一个小型 3D 空间草稿。
主角是：【名字和身份】。
必须保留的外观特征：【形状、颜色、配饰或其他识别特征】。
它的性格、习惯或主要用途：【填写】。
我设想的环境：【填写；没有想法可写“请提出两个简洁选项”】。
希望表达的感受：【2–3 个词】。

请帮我写一张创作卡：它是谁、住在哪里或在哪里活动、周围需要什么、希望表达什么感受。
解释每件物品如何支持主角的生活、习惯或用途。
基础版本只需要主角、一个承载地面和 1–2 件核心周边，其余标为可选。
给出主角与核心周边的建议位置，并保留一块空地。
不要默认场景必须有树、休息窝、路径或花草；只选择符合主题的内容。
本轮只规划，不生成图片或代码，不假设任何周边模型已经存在。
```

**继续条件：** 你能用一句话解释每件核心物品为什么在这里。保存选定的创作卡文字，下一步将其粘贴到指令中。

## Step 02｜生成场景概念图

**使用工具：** 图像生成工具。**输入：** 上传主角参考图，粘贴刚刚选定的创作卡。**替换：** 场景名、创作卡、关键特征、布局、视觉设定。布局可以直接采用上一步建议。

```text
请根据我上传的主角参考图，为“【主角名】”设计一张“【场景名称】”3D 场景概念图。

创作卡：【粘贴选定的创作卡文字】。
请严格保留主角的【列出关键外形、身体比例、颜色、纹样和配饰】，不要重新设计主角。

场景内容与布局：
承载地面：【形态、表面材质和侧缘颜色】。
主角：【位置与朝向】。
核心物件 A：【名称、用途、位置，与主角的相对大小】。
核心物件 B：【名称、用途、位置，与主角的相对大小；可填无】。
可选点缀：【少量物件及位置；可填无】。
路径：【起点与终点；不需要则填无】。

希望表达【情绪】，采用【视觉风格】，主要颜色为【配色】，光线为【光线描述】。
主角是视觉重点，关键特征清楚可见，物件之间留出空间，避免堆满地面。
从略微俯视的斜前方展示整个场景。地面边界、最高物件顶部和所有主要物件完整入镜，四周留白。
使用简洁的【背景颜色】背景，不加入文字、界面或水印。
这张图用于确定布局与氛围，核心周边之后需要分别制作成独立 3D 模型。
```

**继续条件：** 能看清主角和每件核心周边的相对位置。若不满意，使用下面的单项修改指令，而不是把全部设定重新改一遍。

```text
请修改我上传的场景概念图。
当前问题：【描述看见的问题，例如高物件挡住了主角头部】。
希望达到：【描述可观察结果，例如主角头部完整可见，高物件仍保留遮蔽作用】。
本轮只调整：【位置、大小、镜头或灯光中的一项及具体对象】。
保留主角设计、其他物件、整体风格与配色。所有主要物件和地面边界完整入镜。
```

## Step 03｜拆成可制作的资产清单

**使用工具：** 能读取图片的文字 AI 或 Codex。**输入：** 上传选定概念图，填写已有主模型信息。此时还没有周边 GLB 是正常的。

```text
请分析我上传的场景概念图，拆解搭建这个小空间需要的独立资产。
已有主模型：【真实文件相对路径；尚未放进项目则写“已导出，待整理”】。
基础版本选定的核心周边：【1–2 件对象名称】。

请列出：对象名称、场景作用、建议制作方式、所需输入素材、计划输出、基础必需或可选扩展。
区分“已经存在”“需要生成”“可由代码简单搭建”，计划文件名不能写成已完成文件。
适合独立生成的物件分别输出 GLB，方便以后独立调整大小、位置和朝向。
简单地面、背景和少量简单形状优先交给 Codex；不要为每个重复摆件生成一份文件。
指出概念图中哪些对象被遮挡，不能仅靠裁切得到完整参考图。
本轮只分析，不生成图片、不写代码，也不把参考图片当成已完成模型。
```

**继续条件：** 每件基础周边都有明确制作方式；下一步只挑一件准备参考图。

## Step 04｜准备单物体建模参考图

**使用工具：** 图像生成或编辑工具。**输入：** 上传概念图或目标物件的裁切图。**替换：** 对象、形状、材质、颜色、功能结构。

```text
请根据我上传的参考图，制作一个独立的“【对象名称】”建模参考图，本轮只生成这一个对象。
保留：【整体轮廓、比例、材质、颜色和关键细节】。
必须清楚显示的功能结构：【入口、凹槽、支撑脚、内部空间等；无则填写完整外轮廓】。
移除：【主角、相邻物件、场景地面等不属于此对象的内容】。
如果对象本身包含底座、根部或支撑结构，请保留这些组成部分。

补全被遮挡的轮廓；不可见部分采用与现有设计一致的简洁结构，不凭空添加装饰。
保持【视觉风格】，使用三分之四视角，适当显示侧面和顶部，让对象结构易于理解。
物体完整入镜，顶部、底部与边缘不裁切，四周留白，使用与物体有区分的浅色纯背景。
使用柔和、清楚的光照，不要强烈景深或遮盖结构的阴影，不加入文字、尺寸标注或水印。
这是一张用于生成独立 3D 模型的参考图，不是完整场景图，也不是多个对象的拼图。
```

**继续条件：** 对象完整、关键结构清楚、没有黏连其他物件。补全结果是新的设计推断，需自己认可后再建模。普通浅色背景即可，不必强求透明背景或三视图。

## Step 05｜在 Tripo 生成与检查

**使用工具：** Tripo 网页端。**输入：** 上一步选定的单物体参考图。以当前网页的图像生成模型入口上传图片；若该入口提供文字补充字段，可使用下面的文字。若没有文字字段，直接使用图片，不必寻找不存在的输入框。

```text
根据输入的独立对象参考图生成“【对象名称】”3D 模型。
保留参考图中的【轮廓、比例、材质分区、主要颜色和识别特征】。
必须保留的结构是【开口、内部空间、支撑结构等；无则填完整外轮廓】。
采用参考图已有的视觉风格。只生成目标物件，不加入参考图之外的角色、场景地面、文字或其他物品。
对象应结构完整，便于之后作为独立物件在 3D 场景中摆放。
```

提示词不能保证模型质量。生成后亲自旋转观察正面、背面、侧面和底部，检查开口是否封死、是否破损或多出物件，再选择版本并导出 GLB。按钮名称、额度和文字输入支持需按课堂使用时的界面核验，这里不假定固定操作入口。

## Step 06｜把素材交接给 Codex

**使用工具：** Codex 项目对话。**输入：** 把参考图和导出的 GLB 放进自己的练习项目文件夹，再发送以下指令。此步骤创建后续步骤使用的素材清单和进度文档。

```text
请先阅读当前项目说明与已有代码，核对当前项目及子目录中的实际素材。
我的场景主题：【场景名称】。
主角：【主角名称】；计划使用的核心周边：【对象名称列表】。

图片参考与模型分开列出，记录准确文件名、相对路径、大小、用途和来源。
不要仅凭名称推断内容；不能确认的内容或来源标“待确认”。检查文件名是否有前后空格。
保留原始文件。对确认要使用的 GLB，复制到 public/models/，采用无空格的稳定文件名；已有同用途副本时先核对再复用，不覆盖不同文件。
记录原始路径与网页副本的对应关系。PNG 不能算作已完成 GLB，未生成的物件标为缺失。
创建或更新 docs/asset-inventory.md 和 docs/workshop02-progress.md，保存清单与实际状态。
本轮只核对和整理素材，不改变场景，不导入模型，不部署。
```

**继续条件：** 清单中的基础模型真实存在，路径已确认。之后从清单复制路径，不猜文件名。

## Step 07｜先搭建基础空间

**使用工具：** Codex。**输入：** 已整理的练习项目、概念图，以及你选定的布局文字。如果项目已经搭好空间，跳过本步骤，直接进入 Step 08。

```text
请先阅读当前项目说明、代码、docs/asset-inventory.md 与 docs/workshop02-progress.md。
基于我提供的概念图，在这个练习项目里建立能运行的基础 3D 空间。
已有项目则沿用其结构；若只有素材，建立 Vite + Three.js 项目，锁定依赖并保留 lockfile。

场景主题：【填写】。
地面形状、顶面与侧缘：【填写】。
背景、配色与光照氛围：【填写】。
主角占位位置：【填写】。
核心周边占位：【逐件写名称、位置与大致相对大小】。
使用略微俯视的斜前方初始相机，完整展示地面和所有占位物，保留中央空地与画面留白。

本轮只用明确标注的简单几何占位，不加载 GLB，不制作复杂装饰。
加入鼠标拖动环绕、合理范围的滚轮缩放、重置视角按钮和窗口尺寸自适应。
启动本地预览，提供实际地址与启动方法，不假定端口一定是 5173。
实际检查画面、环绕、缩放、重置和控制台。无法执行的检查标为未测试。
更新 docs/workshop02-progress.md，记录完成内容和验证结果。本轮完成后停止，不新增互动或部署。
```

**继续条件：** 能打开预览、看见基础空间并观察占位关系。先修正空间和镜头，再导入真实模型。

## Step 08｜逐个导入模型

### 08A：先导入主角

**使用工具：** Codex。**输入：** 从素材清单复制主角模型的实际网页副本路径。填写“占地宽度约为岛面宽度的四分之一”等相对比例即可，不必自行计算坐标。

```text
请阅读现有场景、docs/asset-inventory.md 和 docs/workshop02-progress.md。
本轮只导入主角“【名称】”，模型文件是【清单中的实际相对路径】。
保留现有地面、灯光和观察功能，其他物件保持现状。

使用 GLTFLoader 加载模型，加载成功后再移除对应占位形状与标签。
保留原材质、贴图和身体比例，根据实际包围盒等比缩放。
期望大小：【相对地面或核心物件的大小】；位置：【位置】；朝向：【朝向】。
必须清楚展示：【主角关键特征】。
确认上下方向，按真实支撑部位接触地面；不能仅依据尾巴或悬垂配件的最低点判断落地。

添加简洁加载与失败提示；只有可计算时显示真实百分比，否则显示“正在加载”。
失败时保留占位并说明文件与错误，不把占位算成成功导入。
在浏览器检查模型请求、初始全景、侧面接地、环绕、缩放、重置、刷新和控制台。
记录模型路径、缩放、位置、旋转、实际通过与未测试项，并提供截图和预览地址。完成后停止。
```

### 08B：每次导入一件核心周边

**输入：** 一件核心周边的实际 GLB 路径。每件物件单独发送一次。

```text
继续当前项目，先阅读素材清单、进度文档和场景代码。
本轮只导入“【对象名称】”，真实模型路径为【相对路径】。
它的用途是【用途】，应放在【位置】，大小为【与主角的相对比例】，朝向【方向或开口所朝区域】。
它与其他物件应形成的关系是【例如靠近主角但留出通道】。
保留已完成模型的外观、主角大小与现有观察功能。
保留新模型材质与贴图，使用等比缩放，使其保持独立可调。
加载成功后才移除对应占位和标签，失败时显示真实错误。
从初始视角和侧面检查落地、遮挡与穿插，主角的【关键特征】必须清楚可见。
验证刷新加载、环绕、缩放、重置和控制台，更新进度文档，未测试项如实记录。完成本件后停止。
```

### 08C：可选装饰与重复物件

**输入：** 只填写你已经决定加入的点缀；没有就跳过。

```text
在当前已验证的基础场景中补充少量【点缀名称】，先核对素材清单和已有代码。
摆放范围：【位置】；数量：【数量】；相对大小：【大小】。
已有真实 GLB 时复用一次加载结果；没有时使用简单几何，并明确记录制作方式。
静态重复物件共享几何和材质，不重复下载同一文件；保留原始素材与模型外观。
适度变化朝向和大小，保持中央空地，不遮挡主角的关键特征，不与主要物件重叠。
从全景与侧面检查摆放，验证加载和原有观察功能，更新进度文档并提供截图。
本轮不添加其他资产、复杂动画或新互动。
```

## Step 09｜用观察提出修改

**使用工具：** Codex。**输入：** 当前截图和自己实际观察到的问题。不要照抄讲师遇到的问题；一次只选一个重点。

```text
请先阅读当前场景和进度文档，保留已经满意的部分。
我实际观察到：【描述具体对象、视角和问题】。
我希望达到：【写可观察的效果】。
本轮允许调整：【列出对象以及位置、朝向、间距等允许变化的参数】。
必须保留：【主角大小、关键外观、满意的配色或空间关系】。

请根据这些要求调整现有场景，不增加新资产，不改变模型材质，不新增互动。
修改前后使用相同相机、灯光和画面尺寸截图，方便比较；另从侧面检查接地、遮挡和穿插。
确认主角仍是视觉重点，所有主要物件完整入镜，环绕、缩放和重置保持正常。
在 docs/workshop02-progress.md 中记录我的观察、实际调整、验证结果和未测试项。
提供预览地址与前后截图。完成本轮后停止。
```

**继续条件：** 前后对比能看见你要求的改善，且没有引入新的遮挡或接地问题。若未改善，继续描述实际结果，不把“代码修改了”当成验收通过。

## Step 10｜检查与保存

**使用工具：** Codex。**输入：** 当前练习项目，无需预先知道模型数量和启动端口。

```text
请完成当前 Workshop 02 项目的收尾检查，先阅读项目说明、实际运行配置和进度文档。
核对网页实际使用的模型路径与独立文件数量；重复实例不重复计为独立资产。
不要重新处理已经完成的模型，本轮不要求压缩模型。
只停止本项目的本地服务，再按项目配置重新启动，提供实际访问地址。
在浏览器检查所有实际使用模型、刷新加载、环绕、缩放、重置与控制台错误。
执行项目配置中真实存在的生产构建命令，并分别记录构建结果和浏览器检查结果。
如果工具无法完成某项检查，明确标为未测试；普通刷新不能写成禁用缓存冷加载。

保留完整项目、原始素材、网页模型、配置文件和 lockfile。
更新 README 的环境准备、安装、启动、停止、再次打开方法，以及实际预览地址说明。
更新进度文档，纠正与当前状态不符的占位文字，同时保留明确标为历史的阶段记录。
列出 Workshop 03 可探索的区域、内容和互动选项，供我选择，不直接实现。
不新增互动、不自动部署、不推送代码。报告保存位置、验证结果与尚未完成项。
```

**完成条件：** 项目重新打开后可以按说明运行；你知道哪些检查通过、哪些未测，也能提出自己下一步想探索的方向。

---

本模板是按教学顺序整理的通用指令，不表示所有替换主题都已经实跑验证。可替换的是角色、世界、资产和视觉选择；每一步的文件核对、观察、验收与记录仍然需要实际完成。
