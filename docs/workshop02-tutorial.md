# Workshop 02 项目技术参考（历史稿）

> 面向零基础学习者的当前主教程已整理到 [docs/workshop02/README.md](workshop02/README.md) 和 [docs/workshop02/Workshop02_完整教程.md](workshop02/Workshop02_完整教程.md)。本文件保留为项目参数、证据和实现细节参考，避免与学生版教程混淆。

## 芽芽的林间秘密花园：从角色模型到可观察的 3D 网页场景

本教程记录本项目实际完成的 Workshop 02 工作流。它不是抽象示例：文件名、路径、参数、验证结果和未完成事项均以当前项目为准。

> 当前成果：一个可在本地运行的 Three.js 场景。场景包含芽芽、树、苔藓休息窝、灯笼、果篮、叶形水碗、蘑菇凳、踏脚石和少量花草；支持环绕观察、滚轮缩放和重置视角。
>
> 当前未实现：故事卡片、点击模型互动、角色移动、碰撞系统、声音、公开部署。这些内容留给 Workshop 03。

## 1. 你将完成什么

最终场景的空间关系如下：

- 芽芽：前方中央，是视觉重点。
- 树：左后方，为休息区提供遮蔽。
- 苔藓窝：右后方，开口朝向场景中央。
- 灯笼：窝旁。
- 果篮与叶形水碗：右前方生活区。
- 蘑菇凳：左侧树下。
- 五块踏脚石：从小岛前缘沿轻微弯曲路径通往苔藓窝。
- 四簇花草：岛边和树根附近，中央空地保持清楚。

## 2. 课前准备

需要：

- Node.js 与 npm。
- Workshop 01 的芽芽模型或本项目提供的示例模型。
- 一个可以查看本地网页的浏览器。
- 当前项目目录：`workshop2/`。

本项目实际验证环境为 Node.js 24.21.0、npm 11.19.0。模型文件较大，首次加载需要等待下载和解析。

## 3. 启动项目

在项目根目录运行：

```sh
npm ci
npm run dev
```

打开：`http://127.0.0.1:5173/`

操作方式：

- 鼠标拖动：环绕观察。
- 滚轮：缩放。
- 「重置视角」：恢复完整初始构图。

构建检查：

```sh
npm run build
npm run preview
```

开发依赖和版本由 `package-lock.json` 锁定。当前构建可以通过，但会提示主 JavaScript 包超过 500 kB；这不是构建失败。

## 4. Step 01–05：从想法到资产清单

### Step 01｜确定主题

先写下三件事：

1. 主角是谁？——温和、好奇的三尾森林灵狐芽芽。
2. 它需要什么空间？——一个安静、能晒午后阳光、可以休息的角落。
3. 观众从哪里看？——略微俯视的斜前方，完整看到小岛和主要物件。

### Step 02｜根据概念图拆解资产

把概念图分成三类：

- 场景基础：草地小岛、背景、灯光、相机。
- 主要资产：芽芽、树、苔藓休息窝。
- 周边资产：灯笼、果篮、叶形水碗、蘑菇凳、踏脚石、花草。

本项目保留参考图与实际模型的区别：PNG 是参考图，GLB 才是网页实际加载的模型。

### Step 03｜核对文件名

原始素材保留在项目根目录。芽芽原文件名开头带一个半角空格：` 芽芽.glb`。不要直接重命名或删除原文件，应复制出稳定网页路径：

```text
 芽芽.glb                 → public/models/yaya.glb
forest_tree.glb           → public/models/forest-tree.glb
moss_rest_nest.glb        → public/models/moss-rest-nest.glb
woodland_lantern.glb      → public/models/woodland-lantern.glb
fruit_basket.glb          → public/models/fruit-basket.glb
leaf_bowl.glb             → public/models/leaf-bowl.glb
peach_mushroom.glb        → public/models/peach-mushroom.glb
Garden_Stepping_Stone.glb → public/models/garden-stepping-stone.glb
Cream_Daisies.glb         → public/models/cream-daisies.glb
```

原文件始终保留。参考 PNG 不计入“已完成模型”。

## 5. Step 06–07：建立基础空间

先不要加载 GLB，用简单几何验证空间关系：

- 用圆润的不规则挤出几何制作低矮草地小岛。
- 顶面使用鼠尾草绿色，侧缘使用暖土色。
- 背景使用浅奶油色。
- 加入柔和午后方向光、天空补光和基础阴影。
- 相机从略微俯视的斜前方开始，并让整个小岛完整入镜。
- 用临时几何标记芽芽、树、窝、灯笼、果篮、水碗和蘑菇凳的位置。

占位物只表示布局，不能当作模型导入完成证据。占位阶段的重点是：主角前方中央、树左后方、窝右后方，三者之间保留空地。

## 6. Step 08A–08F：逐个导入真实模型

每次只处理一个模型，使用 `GLTFLoader`：

1. 请求 GLB。
2. 有总字节数时显示实际进度；未知时显示「正在加载」。
3. 解析完成后计算包围盒。
4. 等比缩放、调整朝向和位置。
5. 将包围盒底部对齐岛面。
6. 确认成功后才移除对应占位物和标签。
7. 失败时显示文件路径与错误，并保留回退几何。

### 芽芽

- 目标高度：2.65。
- 位置中心：约 `x=-0.45, z=1.05`。
- Y 轴旋转：约 `0.2 rad`。
- 岛面高度：`0.57`。
- 保留原始材质、贴图、奶油白身体、桃色细节、三条尾巴和绿色配饰。
- 正面检查脸、耳朵、尾巴；侧面检查脚部接地。不能因为尾巴最低点而误判脚悬空。

### 树、苔藓窝、灯笼、果篮和水碗

每件资产都独立加载、独立摆放。尺寸依据实际包围盒，而不是直接套用占位几何尺寸。检查内容包括：

- 是否面向正确方向。
- 是否完整留在小岛范围内。
- 是否与芽芽、路径和其他生活物件重叠。
- 是否保留原模型材质和贴图。
- 失败时是否仍明确显示失败，而不是误报成功。

## 7. Step 08G：补齐蘑菇凳、踏脚石和花草

### 蘑菇凳

加载一次真实 GLB，按芽芽尺寸等比缩放为低矮小凳，放在左侧树下。成功后移除蘑菇凳占位标签。

### 踏脚石

加载一次石头 GLB，复制同一场景对象生成五个实例。实例共享几何和材质，不重复下载文件。每块石头有轻微尺度、旋转和位置变化，并沿前缘通往休息窝。

### 花草

加载一次花草 GLB，复用四个副本。花草只放在岛边和树根附近，不遮挡芽芽脚和尾巴，不铺满中央空地。

## 8. Step 09：根据观察调整空间关系

当所有物件齐全后，不急着新增资产，先观察“空间是否像一个可以生活的地方”。本项目的调整是：

- 五块踏脚石改成轻微弯曲路径：
  `[-.35,2.72]`、`[.05,2.18]`、`[.52,1.64]`、`[1.02,1.12]`、`[1.42,.58]`。
- 树中心约 `x=-2.05, z=-0.95`，Y 旋转约 `-0.12`。
- 窝中心约 `x=1.85, z=-0.90`，Y 旋转约 `-0.08`。
- 灯笼、果篮、水碗组成右侧生活区。
- 中央空地不增加新资产。

验证时使用同一相机视角保存修改前后截图，再从侧面检查遮挡、接地和穿插。

## 9. Step 10A：模型轻量化与加载验证

先统计网页实际使用的独立 GLB，而不是把 5 块石头和 4 簇花草重复计成 9 个文件。当前网页请求 9 个独立 GLB，场景实例共 18 个，原版合计约 532.88 MiB。

审计结论：主要体积来自高密度几何，不是贴图。芽芽属于视觉重点，暂不做激进优化。

### 只试跑一个优化副本

选择体积最大的踏脚石，原版保留在：

```text
public/models/garden-stepping-stone.glb
```

优化副本写入：

```text
public/models/optimized/garden-stepping-stone.glb
```

使用 glTF Transform CLI 4.2.1 的温和参数：

```sh
npm exec --yes @gltf-transform/cli@4.2.1 -- optimize \
  public/models/garden-stepping-stone.glb \
  public/models/optimized/garden-stepping-stone.glb \
  --compress false \
  --texture-compress false \
  --simplify true \
  --simplify-ratio 0.7 \
  --texture-size 1024 \
  --palette false \
  --instance false \
  --join false
```

结果：67,460,144 B → 50,922,040 B；三角面 1,940,434 → 1,358,302。三张 2048² JPEG 贴图保留，没有引入 Draco 或 Meshopt 解码器。

网页通过 `stoneModelFile` 单一常量切换原版和优化版。当前接入优化版，其他模型继续使用原版。

### 对比和警告

用相同视口保存原版与优化版截图，目检石块轮廓、颜色、路径连续性和接地关系。当前对比没有发现明显差异。

`validate` 无错误，但有一条切线警告：材质需要切线空间，网格没有显式 tangent，运行时会生成 tangent。当前浏览器显示正常；Safari、Firefox、真实手机和低端 GPU 仍未测试，不能宣称所有环境无风险。

## 10. Step 10B：停止、重启和交付

关闭旧服务后重新启动：

```sh
npm run dev
```

打开 `http://127.0.0.1:5173/`，确认：

- 9 个模型全部显示成功。
- 踏脚石复用五块，花草复用四簇。
- 环绕、滚轮缩放和重置视角正常。
- 控制台没有新增 error/warn。
- 页面不再显示“蘑菇凳为占位”等过时成功文字。

构建并保存 `dist/`、`public/models/`、`src/`、`docs/` 和 `package-lock.json`。不要删除原始模型。

## 11. 当前验证边界

已验证：本地开发预览、模型加载、刷新重载、桌面浏览器环绕、缩放、重置、构建、重启恢复、优化石块对比。

## 12. Workshop 03 衔接

建议从三个方向继续：

- 区域：增加林间小径、浅溪边、采光林隙或小型花圃。
- 内容：树洞入口、溪边石桥、季节性植物、萤火虫、收集物和新的生活道具。
- 互动：点亮灯笼、打开树洞、收集果实、花草微动画、环境音或昼夜变化。

Workshop 03 的第一轮目标可以限定为：新增一个区域、加入一种可重复使用的互动、根据体验反馈调整一次布局，并完成一个可公开访问的版本。
